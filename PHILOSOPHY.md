# The SkillRoll philosophy

Prompts deserve tests.

A failing eval should precede a prompt fix.
Verified change is better than hopeful change.
Readable evidence is better than a mysterious score.

Nondeterminism needs repeatable evidence, not pretend determinism.
Judge meaning with models; check exact facts with code.
A case's World should simulate reality without touching production.
A pass supports one claim; it proves nothing universal.

Manual testing should be useful immediately.
CI warning should come before CI gating.
Gates are earned by stable, specific, actionable failures.
A red build people ignore is worse than an honest warning.

One eval should test one important behavior.
One skill should do one thing well.
Separate concerns: judgment in skills, certainty in scripts, knowledge in references.
Compose complexity; do not grow prompt monstrosities.

Plain text is a feature.
Every artifact should explain itself.
Coverage should be reviewable, not merely plentiful.
An honest “cannot evaluate this well” beats a rubber stamp.

Simple setup is better than comprehensive setup.
Advanced rigor should be a path, not an entrance fee.
Complexity must repay its cost with trust.
Practical protection beats theoretical completeness.

SkillRoll should catch regressions in nondeterministic skills.
It should fit any prompt repository that currently has no evals.
It is not a formal proof system or a universal eval laboratory.

Every change must preserve these principles.
If it cannot, stop before implementation: ask why, or change the philosophy openly.
